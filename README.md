# Warhammer AI Store

Контрольная работа Маттиева Рустама Алимжоновича, группа САПР-2.1, 2026 г.
Основа — курсовая TPLab2-3. Исходная курсовая сохранена в соседней папке.

Два самостоятельных REST-сервиса: магазин на Django и опубликованный сервис рекомендаций в Cloudflare Workers. Два клиента: браузерный HTML/CSS/JavaScript и отдельный Python/Tkinter. ИИ — Workers AI, `@cf/meta/llama-3.3-70b-instruct-fp8-fast`.

## Что установить на другом компьютере

- Python **3.11 или новее**, с компонентами pip и Tcl/Tk. В установщике Windows отметьте **Add python.exe to PATH**. Для Linux дополнительно может потребоваться пакет `python3-tk` и поддержка venv.
- Любой современный браузер.
- Интернет для установки пакетов и ИИ-подбора. Каталог, корзина и заказы работают с локальной БД.

**Node.js, npm, Wrangler, Docker, Microsoft Word и отдельный сервер БД для запуска магазина не нужны.** Word нужен только для повторного формирования PDF из редактируемого отчёта.

## Быстрый запуск Windows

1. Распакуйте проект в доступную для записи папку. Не переносите чужое виртуальное окружение.
2. Запустите `setup.cmd`. Он создаст `.venv`, установит зависимости, применит миграции и наполнит каталог.
3. Для работы с уже размещённым Worker перенесите свой приватный `.env` на этот компьютер **либо** заполните в созданном `.env` значения `RECOMMENDATIONS_URL` и `RECOMMENDATIONS_API_KEY` из исходного приватного файла. Это ключ нашего сервиса, а не токен Cloudflare. Сам токен Cloudflare нужен только для проверки модели и развёртывания Worker.
4. Запустите `run_server.cmd` и оставьте окно работающим.
5. Откройте <http://127.0.0.1:8000/>.
6. Для второго клиента запустите `run_desktop.cmd`. Сервер должен продолжать работать.

Демонстрационные учётные записи, создаваемые только при первом наполнении:

| Роль | Логин | Пароль |
|---|---|---|
| Покупатель | `demo` | `WarhammerDemo2026!` |
| Администратор | `admin` | `WarhammerAdmin2026!` |

Администрирование: <http://127.0.0.1:8000/admin/>. Создать свою учётную запись администратора можно командой `.venv\Scripts\python.exe manage.py createsuperuser`.

Повторный `seed_demo` не дублирует товары, не меняет существующие пароли и не восстанавливает остатки после покупок. Для явного восстановления учебных остатков: `manage.py seed_demo --reset-stock`.

## Ручная установка в PowerShell

Команды выполняются из папки проекта `WarhammerAI`:

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env  # только если своего .env ещё нет
.\.venv\Scripts\python.exe manage.py migrate
.\.venv\Scripts\python.exe manage.py seed_demo
.\.venv\Scripts\python.exe manage.py runserver 127.0.0.1:8000
```

Во втором окне PowerShell:

```powershell
.\.venv\Scripts\python.exe desktop\app.py
```

Активация окружения и изменение ExecutionPolicy не требуются. На Linux/macOS используйте `.venv/bin/python` вместо `.venv\Scripts\python.exe`.

Если установка пакетов в корпоративной сети сообщает об ошибке сертификата, используйте системное хранилище доверия: `python -m pip install truststore`, затем `python -m pip install --use-feature=truststore -r requirements.txt` из соответствующего окружения. В новых версиях pip системное хранилище используется по умолчанию.

## Другой компьютер как клиент по локальной сети

На компьютере-сервере укажите в `.env` собственный LAN IP, например:

```dotenv
DJANGO_ALLOWED_HOSTS=localhost,127.0.0.1,192.168.1.20
```

Запустите сервер: `.venv\Scripts\python.exe manage.py runserver 0.0.0.0:8000`. Разрешите входящие подключения к порту 8000 в частной сети Windows. На втором устройстве откройте `http://192.168.1.20:8000/`; в настольном клиенте укажите такой же адрес в поле «Сервер» до входа.

Для отдельного GUI-компьютера достаточно Python с Tkinter, файлов `desktop/` и установки `python -m pip install -r desktop/requirements.txt`. Django, база и облачные ключи этому клиенту не нужны. Адрес также можно передать аргументом `python desktop/app.py --server http://192.168.1.20:8000`.

`runserver` и демонстрационные пользователи предназначены для учебного запуска. Внешний публичный сервер потребует HTTPS, WSGI-сервера, собственной конфигурации `DEBUG=0`, `SECRET_KEY`, раздачи статики и новых паролей.

## Как устроен ИИ-подбор

1. Авторизованный клиент отправляет пожелания, общий бюджет, необязательные фракцию и категорию.
2. Django валидирует запрос, отбирает доступные товары и использует актуальные цены со скидками.
3. Отдельный Worker получает не более 50 кандидатов и вызывает настоящую модель через binding `AI`.
4. Worker проверяет ответ модели, Django повторно проверяет товары, количество, цены и общий бюджет.
5. Возвращаются карточки и объяснения на русском языке. Цена и наличие не берутся из текста модели.

Повторный одинаковый запрос кешируется в памяти Django на 5 минут; состав и текущие характеристики кандидатов входят в ключ кеша. Рекомендация не резервирует товар: наличие проверяется ещё раз при оформлении заказа. При недоступности облака возвращается 503; фиктивной замены ИИ нет.

## Развернуть облачный сервис в своём аккаунте без Node.js

Заполните `CLOUDFLARE_ACCOUNT_ID`, `CLOUDFLARE_API_TOKEN`, `CLOUDFLARE_AI_MODEL` и `CLOUDFLARE_WORKER_NAME` в `.env`. Для токена выберите свой конкретный аккаунт и права Workers AI Read/Edit и Workers Scripts Edit. Затем:

```powershell
python scripts/check_cloudflare.py
python scripts/deploy_cloudflare.py
```

Скрипт загрузит `cloud_function/worker.mjs` через Cloudflare REST API, подключит binding `AI`, задаст модель, создаст отдельный случайный ключ сервиса и запишет URL в `.env`. Секреты в консоль не выводятся. Для публикации своего Worker имя должно быть свободным в вашем аккаунте. После изменения `.env` перезапустите Django.

Опубликованный сервис: <https://warhammer-ai-recommendations.canadyleon58.workers.dev/health>. Бесплатный тариф Workers Free имеет лимит Workers AI 10 000 Neurons в сутки; некоторые модели требуют оплаты. Выбранная модель проверена реальным запросом в этом аккаунте. Не подключайте Paid, если нужен запуск в пределах бесплатных лимитов. Условия: <https://developers.cloudflare.com/workers-ai/platform/pricing/>.

## API, отчёт и проверки

- `docs/API.md` — описание контрактов магазина и Worker.
- `docs/openapi.yaml` — OpenAPI магазина; интерактивный просмотр: <http://127.0.0.1:8000/api/docs/>.
- `docs/cloud_openapi.yaml` — OpenAPI отдельного Worker.
- `docs/uml/` — пять UML-представлений и редактируемые исходники.
- `docs/screenshots/` — реальные браузерные и настольные интерфейсы.
- `docs/live_validation.json`, `browser_validation.json`, `gui_validation.json` — результаты реальных интеграционных проверок без токенов.
- `docs/image_sources.json` — источники двенадцати новых фотографий. Цены, остатки и описания — учебные данные.
- Итоговые Word и PDF находятся в соседней папке `Результат`.

```powershell
.\.venv\Scripts\python.exe manage.py test store
.\.venv\Scripts\python.exe manage.py spectacular --file docs/openapi.yaml --validate
```

Для проверки Worker локально дополнительно нужен Node.js с `node:test` (в разработке проверки прошли даже на Node 18): `node --test cloud_function/worker.test.mjs`. Для обычного запуска он не нужен.

Разработческие проверки браузера требуют `requirements-dev.txt` и Chrome (путь задаётся в `scripts/browser_check.py`). `gui_check.py` требует интерактивную сессию Windows. Эти сценарии создают демонстрационные заказы и уменьшают учебные остатки. Для повседневной работы запускать их не требуется.

Повторное формирование отчёта: установите `requirements-dev.txt`, затем выполните `python scripts/make_report.py`. Шаблон оформления без содержимого исходной курсовой включён в `docs/report_template.docx`. Для рендеринга UML нужен Graphviz (`dot` в PATH; для диаграммы последовательности — шрифт Times New Roman). Для точного обновления оглавления и экспорта PDF в Windows используется установленный Microsoft Word: `powershell -ExecutionPolicy Bypass -File scripts/export_report.ps1`. Для чтения уже готовых PDF/DOCX эти инструменты не нужны.

В архив проекта не включены `.env`, виртуальное окружение, токены и рабочая SQLite-база. Они создаются/переносятся при установке.
